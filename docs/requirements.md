# 需求基线（Requirements Baseline）

本文件是这个工程的**需求唯一来源**。模型、测试、覆盖率报告都以这里的 ID 为准。

规则：

1. 每条需求必须有 **唯一 ID**、**可测量的判据**、**验证方法**。
2. 判据里不允许出现"良好""快速""合理"这类不可测量的词。
3. 改需求 = 改版本号；代码或模型变更必须说明影响哪几条需求。

## 1. 高度控制（Altitude Hold）

| ID | 需求 | 判据 | 验证方法 | 测试用例 |
|---|---|---|---|---|
| REQ-ALT-001 | 高度指令阶跃响应不得有过度超调 | 超调量 ≤ 10 % 阶跃幅值 | 仿真试验 | `run_requirements_tests` / ALT-001 |
| REQ-ALT-002 | 高度响应应快速收敛 | 进入 ±5 % 误差带的时间 ≤ 12 s | 仿真试验 | ALT-002 |
| REQ-ALT-003 | 存在质量偏差时不得有稳态误差 | 质量偏差 ±10 % 时，t=60 s 的高度误差 ≤ 0.05 m | 仿真试验 | ALT-003（两个用例） |
| REQ-ALT-004 | 推力指令不得超出执行机构权限 | 限幅后的推力 ∈ [0, 12000] N | 仿真试验 | ALT-004 |
| REQ-ALT-005 | 执行机构饱和退出后不得出现持续振荡 | 末 10 s 高度波动 ≤ 0.02 m | 仿真试验 | ALT-005 |

**设计说明（Rationale）**

- REQ-ALT-003 用 ±10 % 质量偏差模拟"前馈配平不准确"这一真实工况：
  控制器不知道真实质量，只能靠积分项消除偏差。这比"参数完全匹配"的仿真更有说服力。
- REQ-ALT-004 的判据针对**限幅后**的推力，因为控制器输出本身允许超出权限，
  由限幅环节保证执行机构安全。

## 2. 能量管理（Energy Management）

| ID | 需求 | 判据 | 验证方法 | 测试用例 |
|---|---|---|---|---|
| REQ-ENR-001 | 电量下降时应按级别给出告警 | SOC 单调下降过程中，模式依次为 NORMAL(0) → CAUTION(1) → WARNING(2) | 仿真试验 | ENR-001 |
| REQ-ENR-002 | 告警级别不得反向跳变 | 本工况下模式不发生回退 | 仿真试验 | ENR-002 |
| REQ-ENR-003 | 低电量告警阈值准确 | 进入 CAUTION 时 SOC 与 0.30 的偏差 ≤ 0.01 | 仿真试验 | ENR-003 |
| REQ-ENR-004 | 严重低电量阈值准确 | 进入 WARNING 时 SOC 与 0.15 的偏差 ≤ 0.01 | 仿真试验 | ENR-004 |

**设计说明**

- 阈值设了滞回（恢复门限比触发门限高 0.03），防止 SOC 在阈值附近抖动造成告警振荡。
  本工况 SOC 单调下降，因此滞回路径不会被覆盖——这是覆盖率的已知缺口，见 README。
- 真实机型上，WARNING 之后应触发自动下降/就近着陆。本项目只输出模式标志，
  不实现下降逻辑，属于有意裁剪的范围。

## 3. 范围外（Out of Scope）

明确写出来，避免审查时被问"为什么没做"：

- 横向/姿态动力学（本模型是一维垂向）
- 电池电化学模型、热失控传播
- 传感器噪声、故障注入、余度管理
- 适航审定基础（专用条件）条款符合性
- 工具鉴定（DO-330）
